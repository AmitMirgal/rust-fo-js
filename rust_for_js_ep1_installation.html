Getting Rust installed

rustup, cargo, and your first "hello, world"

The JS parallel

JavaScript / Node
You manage your Node version with nvm, and install packages with npm. Two separate tools. nvm install 20 npm install lodash
Rust
Rust collapses this into one tool: rustup manages your Rust version, and cargo handles everything else — deps, build, run, test. rustup install stable cargo add serde
Mental model: Think of rustup as nvm, and cargo as npm + node + npx + jest all rolled into one binary.

Install rustup

1

Run the installer (macOS / Linux)

One curl command — same pattern as nvm.

terminal

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Follow the prompts — press 1 to accept defaults

2

Windows

Download and run the installer from rustup.rs — it's a .exe, no terminal needed to start.

Windows note: You may also need the MSVC build tools (Visual Studio Build Tools). The installer will tell you if so.
3

Reload your shell, then verify

terminal

source ~/.cargo/env # or open a new terminal tab rustc --version # rustc 1.x.x (...) cargo --version # cargo 1.x.x (...)

The toolchain — what just got installed

rustup

≈ nvm

Manages Rust versions. Lets you switch between stable / beta / nightly.

rustc

≈ node (the runtime/compiler)

The Rust compiler. You rarely call this directly — cargo does it for you.

cargo

≈ npm + npx + jest

Build, run, test, add deps, publish. Your daily driver.

Good news: Unlike JS, there is no "which package manager should I use" debate. Everyone uses cargo. It ships with Rust and it's official.

Your first project

Node
mkdir my-app && cd my-app npm init -y node index.js
Rust
cargo new my-app cd my-app cargo run

cargo new creates a ready-to-run project. Inside you'll find:

project structure

my-app/ ├── Cargo.toml ← like package.json (project metadata + deps) └── src/ └── main.rs ← your entry point (like index.js)

src/main.rs — what cargo generated

fn main() { println!("Hello, world!"); }

Run it with: cargo run

What JS devs find surprising

Compilation step: There's no "just run the file." Rust compiles to a native binary first. cargo run does compile + run in one step, so it feels seamless — but the first build takes a few seconds. Subsequent builds are incremental and fast.
~/.cargo, not node_modules: Dependencies download to a global cache at ~/.cargo — not inside your project folder. No more 300mb node_modules per project. Your actual build output lands in target/.
Cargo.lock: Like package-lock.json, Cargo.lock pins exact dependency versions. Unlike JS convention, you should commit Cargo.lock for binaries (applications). Libraries omit it — cargo handles the nuance automatically.
